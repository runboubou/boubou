# Spec: Local conversation evidence

**Problem:** A terminal export can show repeated assistant text and context clearing, but it does not contain the user's audio, capture timing, or playback state. It cannot distinguish repeated model output from repeated/incorrect input or false voice detection. Add reproducible local evidence before changing generation or echo policy.

**Behavior:** `boubou run liquid --offline --record-session DIR` explicitly enables recording for microphone mode, including manual mode. The ordinary command remains unchanged and writes no new conversation content. This is a diagnostic facility, not a repetition fix or an additional inference pipeline.

- Create a new directory (0700 on Unix) with new private files (0600). Never overwrite an existing destination. Record an application/platform/mode header and relative event times in `events.jsonl`.
- Save only audio successfully sent to the model, grouped by the existing input-turn identity, as `user-NNNNNN.wav` (PCM16 mono 16 kHz). Partial input committed by pause is marked as not requesting a response. Pending input discarded by pause is not recorded as submitted speech.
- Save accepted generated audio as `assistant-NNNNNN.wav` (PCM16 mono 24 kHz), and text deltas with the corresponding submitted turn in the journal. Filtered late output stays excluded. These files are not proof that the user heard every sample: playback can lag, be interrupted, or fail.
- Record capture starts/ends, interruption requests with queued playback counts, pause/resume, response completion/cancellation, and context-clear boundaries. The journal does not invent user transcripts or determine who spoke. It records neither continuous ambient audio nor raw audio while paused.
- Use one bounded background writer, with nonblocking admission, bounded individual entries, and a conservative 256 MiB session budget. Do not block the conversation loop on disk writes. Finalize WAV files when turns end and on ordinary shutdown, including Ctrl+C. Bound finalization waiting to two seconds and explicitly report incomplete output if it cannot finish.
- Print a privacy notice before opening the microphone. Nothing is uploaded; the user owns retention and sharing. Use only synthetic content in committed tests. Do not include actual conversation exports, recordings, or personal names in the repository.

**Failure cases:** Reject existing destinations, missing parents, incompatible `--input`/recording arguments, and write failures. Queue overflow or budget exhaustion stops the recording-enabled conversation with an explicit error rather than silently omitting evidence. Always retain the original runtime failure if finalization also fails. Abrupt termination or a failed writer can leave partial evidence; absence of a normal `session.end` is not success. A `session.end` event alone is not proof that finalization succeeded; the CLI must also report no recording failure.

**Scope:** Extend the current microphone loop and reuse the existing turn queue, output filtering, WAV library, and file-input replay path. No new dependency, cloud transcription, automatic recording, repetition heuristic, model upgrade, sampling change, or model adapter framework. This does not make the current voice backend compatible with every LFM3 modality.

**Acceptance:** Ordinary tests cover exact input/output PCM and text association, context boundaries, partial paused input, Drop finalization, private permissions, destination preservation, queue failure, writer failure, budget exhaustion, and opt-in CLI constraints. Run the repository's formatting, Clippy, test, build, and native-harness compilation checks on the final candidate. Real-model repetition, automatic/manual device comparisons, acoustic echo, and capture overhead are **NOT RUN** until tested on a permitted Mac; synthetic success does not establish conversational quality.

**Reproduction:** Record a short English conversation with an explicitly permitted microphone/speaker combination. Include idle silence, distinct questions, a correction, an interruption, and a goodbye followed by silence. Keep the same model/backend/devices between automatic and manual controls. Review user WAVs for the actual submitted speech and compare assistant text with generated WAVs. Replay selected input WAVs through the existing `--input` mode without opening devices. Replaying standalone WAVs does not reproduce timing, pause-only input, or cancellation history; replay within the same context epoch and label those limitations. Record source commit, model/backend identity, macOS, and device names alongside the local evidence before sharing a redacted subset.
